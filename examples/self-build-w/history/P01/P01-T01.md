# P01-T01 — Outcome word at the end of every run

- Date: 2026-10-13
- Model: opus (attempt 2)
- Cost: $3.99
- Risk: high

## Summary
Re-applied the outcome word. Every run end records VERIFIED, BLOCKED, BUDGET_STOP, STALLED or FAILED in state meta `outcome` (cleared at run start), a `run_end` event, the log, run.json `word`, and the start of the run_done/fatal/budget notification text. The design is the one from ADR 0001: outcome_word(), a `word` argument on Stop, and Orchestrator._end_word(). Return values are unchanged. `ap status` prints `outcome: <word>` only when the meta key is set, and report.status_line shows `Done <word>`; report.py is named in scope_additions. Ruff passes, and the full WSL suite (wsltest_self.sh) gave 951 passed, 1 skipped, 0 failed.

## Acceptance criteria
- A run that completes the plan stores outcome VERIFIED and the run_done notification starts with VERIFIED
- A run with a parked task stores BLOCKED
- A run stopped by budget_usd.total stores BUDGET_STOP
- ap status prints the outcome line when the meta key is set and nothing new when it is not
- All existing tests pass unchanged

## Decisions
- BUDGET_STOP means a limit the owner set ended the run: a budget cap, the session limit or the .agent/STOP file. Any non-fatal Stop without a word maps to it. A fatal Stop without a word is FAILED.
- A Stop names its word at the raise site (Stop(..., word='STALLED') for a vendor outage and for the same-error checklist). The word is never parsed from the reason text.
- Orchestrator._end_word() is the only writer of the outcome word in a normal run. run_supervised writes FAILED itself for the repeated crash with no task in flight.
- The title word comes from run.json `word` in report.status_line, so the ap watch, dashboard and web titles all show it. dash_term.py and dash_web.py needed no change.
