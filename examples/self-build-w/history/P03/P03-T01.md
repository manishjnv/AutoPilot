# P03-T01 — review.scope key and the review on medium and high tasks

- Date: 2026-10-13
- Model: opus (attempt 2)
- Cost: $2.53
- Risk: high

## Summary
Added review.scope (critical | all). Orchestrator.review_due(task) is the one rule: review.enabled and (risk critical, or scope all and risk above low, using effective_risk). review() and parallel_batch() both use it, so tasks that are due a review stay serial and every merged diff above low risk is reviewed. The review prompt holds only the task spec, the diff and the gate's test output (review_tests(gate)); the phase goal and decisions are gone from review.md. config validates the value, defaults() fixes the code default at critical, and the template sets scope: all. Verified on WSL: 967 passed, 1 skipped (the known CRLF tour test deselected); ruff clean.

## Acceptance criteria
- review.scope: all reviews a medium task and a finding blocks the merge
- review.scope missing or critical keeps today's behaviour (only critical tasks)
- The review prompt contains the acceptance criteria and the diff and nothing from the build session
- config validation rejects any other value with a plain sentence
