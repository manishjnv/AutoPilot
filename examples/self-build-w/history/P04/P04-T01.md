## Summary
Added autopilot/receipt.py (HMAC-SHA256 signed receipt, key in ~/.autopilot/receipt.key, mode 0600, AUTOPILOT_HOME respected). close_phase now writes and commits receipt.json after the docs commit, and `ap verify [phase]` prints `P01 ok` or `P01 CHANGED: ...` and exits 1 on a problem. tests/test_receipt.py has 5 passing tests on the Windows host. Ruff is clean. I did not run the full suite or the WSL script.

## Acceptance criteria
- close_phase writes receipt.json with a signature
- ap verify prints ok for an untouched phase and exits 0
- Editing PROOF.md makes ap verify print CHANGED and exit 1
- A different key makes ap verify report a bad signature
- The key file is never committed: .agent/ ignore rules or the home folder location guarantee it

## Decisions
- The key lives in the home folder, not .agent/, so it can never be committed — meets the acceptance rule without a new ignore rule
- Orchestrator.write_receipt runs after docs_phase and makes its own commit, so the receipt's commit field is the phase-close/docs commit; a failure only logs a warning and never holds the phase
- check() reports a changed file by bare name, a missing file as '<name> missing', and a wrong key as 'bad signature'
