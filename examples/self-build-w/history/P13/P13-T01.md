## Summary
Added the thin VS Code extension in vscode/. It has the three commands (`autopilot.start`, `autopilot.answer`, `autopilot.stop`), which send `ap start`, `ap answer` and `ap stop` to a reused terminal named Autopilot. It also has the `autopilotStatus` Explorer webview view. The view reads the port from `.agent/status.port` (default 8765) and builds an iframe URL through `asExternalUri`. It uses a CSP with only that frame source, and shows "run `ap` first" when nothing answers. `npx tsc --noEmit` passes (node is on PATH), the 3 new manifest tests pass, and ruff is clean. I did not run the WSL suite.

## Decisions
- The extension reads the port file through vscode.workspace.fs and probes the page with fetch (tsconfig lib includes DOM), so @types/node is not needed and devDependencies stay at @types/vscode and typescript — the task allows only those two.
- The webview probes the page before showing the iframe, because the port file is not removed when a run ends and can be stale.
