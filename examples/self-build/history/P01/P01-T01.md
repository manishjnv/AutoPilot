## Summary
Added optional task key `status` (only `done`) to plan.py with validation naming the task id. sync_plan records done tasks as done (note 'done before Autopilot') when the row is new or pending, and never touches running/blocked/skipped/done tasks. Verified by 7 new tests in tests/test_adopt.py, ruff, and 35 existing tests in three files. The background full-suite run was killed at its time limit and the WSL script was not reachable, so neither was confirmed.

## Acceptance criteria
- A plan with 6 tasks marked `status: done` and 2 open tasks: after sync_plan the state has those 6 as done and `next_ready` returns the first open task
- `status: blocked` (or any value other than done) in plan.yaml fails validation with a message naming the task id
- A task already blocked or running in the state DB is not changed by a `status: done` in the plan
- Existing plan.yaml files without `status` load and behave exactly as before (existing tests pass unchanged)
