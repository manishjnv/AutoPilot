## Summary
Added kiro, cursor and aider presets to PRESETS in autopilot/backends/command.py, following the ADR. The model option is --model for these three (_MODEL_OPT), and a {prompt_file} placeholder lets aider read the prompt from a temp file outside the worktree that is removed after the run. New parametrized tests run each preset through CommandBackend with a fake executable of that name on PATH and check the parsed report, the flags, the model flag, unsafe model names, and that codex/gemini/opencode are byte-identical. Ruff is clean and the full WSL suite passes (553 tests).

- model_flag works for each new preset (mapped model gives the flag; unsafe model names still raise)

## Decisions
- aider preset uses --message-file {prompt_file}; CommandBackend writes a temp file (system temp dir) only when the template contains {prompt_file}, still pipes stdin, and deletes the file afterwards — aider has no stdin prompt and /dev/stdin fails on Windows
- model option is --model for kiro/cursor/aider via _MODEL_OPT, -m for the others — aider -m means --message
- kiro preset has no positional _ASK (a positional argument disables stdin); cursor keeps _ASK + undocumented stdin
