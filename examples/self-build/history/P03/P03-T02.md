## Summary
Added detect_runner(env=None) to autopilot/doctor.py: a RUNNERS table (claude, kiro-cli, cursor-agent, codex, gemini, aider) checked in order with shutil.which on env PATH; a non-empty documented key variable counts first, then check_login for claude or a read-only status command (whoami / status / login status) via run_proc with LOGIN_TIMEOUT=10, exit 0 without logged-out wording. _run and check_login got a defaulted timeout kwarg. 9 tests with fake executables on a tmp PATH cover every acceptance criterion; ruff clean, full WSL suite 562 passed.

## Acceptance criteria
- PATH with only a fake `kiro-cli` that reports logged in -> detect_runner returns `kiro`
- PATH with fake `claude` (not logged in) and fake `kiro-cli` (logged in) -> returns `kiro`
- PATH with fake `claude` logged in and fake `kiro-cli` -> returns `claude_cli` (order respected)
- Empty PATH -> None; a login check that hangs is stopped by the timeout

## Decisions
- detect_runner checks key variables before running any status command; an empty key does not count; a status command counts only with rc 0, no timeout and no LOGGED_OUT wording — exit codes are undocumented
- doctor.LOGIN_TIMEOUT (10 s) is the single timeout for login checks; tests lower it with monkeypatch
