# P03-T03 — Preflight writes the detected runner to project.yaml

- Date: 2026-10-11
- Model: opus (attempt 1)
- Cost: $2.29
- Risk: high

## Summary
preflight(cfg) now reads the raw project.yaml. When it sets no backend, command or preset, preflight calls detect_runner and writes backend/preset as a comment-keeping text edit that is parse-checked before the write. It prints `runner: <binary> (found on PATH)`, or prints the Claude Code install command and the supported CLIs and returns False when none is found. The template backend line is commented out and config.defaults() keeps claude_cli as the in-memory default. 8 new tests, including a smoke test where a fake kiro-cli runs one task to done through the Orchestrator; WSL suite 570 passed, ruff clean.

## Acceptance criteria
- PATH with only a fake kiro-cli and no agent.backend in project.yaml -> project.yaml gets agent.backend: command and agent.preset: kiro, comments kept, the runner name is printed
- Smoke: after that preflight, one fixture task runs end to end with the fake kiro-cli and its state is done
- A project.yaml with agent.backend already set is never changed by preflight
- No runner on PATH -> preflight returns False and prints the install command
- Existing projects with `backend: claude_cli` behave as before (existing tests pass unchanged)

## Decisions
- default agent.backend claude_cli lives in config.defaults(), not the template; preflight decides 'unset' from the raw project.yaml (none of backend/command/preset) — every cfg.get reader stays unchanged
- remember_runner inserts after `agent:` (or appends an agent block) and writes only when yaml.safe_load of the new text gives the old values plus the new keys — a project.yaml is never broken
- no runner detected but claude installed -> no write, claude_cli default (the H2 login offer still runs); AUTOPILOT_CLAUDE_BIN set -> detection skipped as an explicit claude choice
