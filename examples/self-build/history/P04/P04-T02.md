# P04-T02 — Plain `ap`: adopt a project that has code and no .agent/

- Date: 2026-10-11
- Model: sonnet (attempt 1)
- Cost: $0.29
- Risk: medium

## Summary
Plain `ap` in a terminal now decides the case from the folder. An empty folder or one with only dotfiles gets the idea prompt. A folder with code and no .agent/project.yaml is adopted: preflight, quiet init, onboarding with no plan doc, adopt_summary, then the 1/2 start choice. A folder with .agent/ keeps the old banner behavior. Verified by new tests for all three cases, including no questions without a terminal; the quickstart and adopt tests pass (30 passed, 3 skipped), ruff clean, WSL script not run.

## Acceptance criteria
- Empty fixture folder with a TTY -> the idea prompt is shown (existing behavior)
- Fixture with source files and a PLAN.md and no .agent/ -> init and onboarding run, the summary with done/open/next is printed, and answering 2 does not start the run
- Fixture with .agent/ present -> no onboarding runs; the banner and next steps are printed
- Without a TTY, plain `ap` never asks a question in any of the three cases

## Decisions
- folder_case(root) in cli.py returns agent, empty or code; entries that start with a dot do not count as content, so a bare git repo is empty — matches the 'only dotfiles / bare git repo' rule
