# P06-T01 — Autopilot block in IDE rule files and CLAUDE.md

- Date: 2026-10-11
- Model: sonnet (attempt 1)
- Cost: $0.60
- Risk: medium

## Summary
cmd_init now calls write_ide_rules(): it appends or creates one marked Autopilot block in Cursor (.mdc with alwaysApply), Kiro steering, Copilot instructions, GEMINI.md and AGENTS.md when the IDE marker exists. The user's bytes are never changed and a second init writes nothing. CLAUDE.md.snippet now lists ap status, ap next and ap start. Verified by 4 new tests and the full WSL suite (580 passed); ruff is clean.

## Acceptance criteria
- Fixture with `.cursor/rules/` -> init writes the Cursor rule file with the block; a second init does not duplicate it
- Fixture with AGENTS.md containing user text -> the block is appended once after the user text, which is unchanged byte for byte
- Fixtures with `.kiro/`, `.vscode/` and GEMINI.md each get their block; a folder with no marker gets only CLAUDE.md
- CLAUDE.md contains `ap status`, `ap next` and `ap start` after init, once

## Decisions
- IDE block uses <!-- autopilot:begin --> markers; new Cursor/Kiro files get front matter first, existing files only get the block appended; skip if the begin marker is present — keeps the user's text byte-identical and init idempotent
- CLAUDE.md is not marked: the existing heading check stays, the snippet only gained the ap command lines

## Follow-ups
- An existing CLAUDE.md that already has the Autopilot heading does not get the new ap command lines
- A project with both .kiro/ and AGENTS.md gets the instruction twice, because Kiro also reads AGENTS.md
