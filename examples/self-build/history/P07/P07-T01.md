# P07-T01 — New-file rule and reasons in the commit message

- Date: 2026-10-11
- Model: opus (attempt 1)
- Cost: $2.12
- Risk: high

## Summary
Added the NEW_FILE_RULE constant to gate.py and the same text, word for word, as a bullet in system.md. task.md now asks for an optional `new_files` [{path, reason}] report field, and the task report schema accepts it without requiring it. A new helper, new_file_lines(report) in orchestrator.py, adds one `new file <path>: <reason>` line per entry to the task commit message on both the sequential and the parallel path; it drops bad entries and keeps every reason on one line. The 5 new tests pass (one runs a fake command-backend agent end to end), 130 tests across the related files pass, and ruff is clean; the full suite was stopped at the 10-minute background limit and the WSL script was not run.

## Acceptance criteria
- system.md contains the new-file rule; the task prompt asks for `new_files` in the report
- The task report schema accepts a report with new_files and one without it
- A fake-agent task run whose report has new_files [{path: src/parser.py, reason: "new module: no file owns the parser"}] gets a commit message containing `new file src/parser.py: new module: no file owns the parser`

## Decisions
- NEW_FILE_RULE lives in gate.py and system.md repeats it word for word; a test checks that the two match. P07-T02 should import the constant and must not copy the text.
- new_file_lines(report) in orchestrator.py is the only builder of commit lines for both commit paths. It keeps only dict entries with a non-empty path, joins whitespace into one line, cuts the reason at 300 characters and uses '(no reason given)' when the reason is empty, because text-only backends do not check reports against the schema.
- The schema field new_files is optional (not in the required list), so old reports stay valid.
