## Decisions
- The new-file guard is opt-in: gate.new_file_reasons, default false in the template, which is also the code default through config.defaults(). The test fakes in about 12 test files add files with no new_files, so the check on by default would break many existing orchestrator tests, and an existing project.yaml must keep working.
- One problem line, 'new file without a reason: <up to 20 paths>[, and N more]. ' + NEW_FILE_RULE. The rule comes last so it stays in the report tail that the retry gets, and its text is imported, never copied.
- Paths in new_files are normalised (backslash to slash, strip, remove './'). Only dict entries with a non-empty path and a non-empty reason count.
